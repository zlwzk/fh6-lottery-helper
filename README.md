# FH6 抽奖助手

《极限竞速：地平线》抽奖（Wheelspin）的**纯外部辅助工具**：帮你在抽到已拥有的车时自动选「已拥有」的处理方式，
一口气把攒下来的抽奖次数刷完，不用手点几千下。

**下载：** [Releases](https://github.com/zlwzk/fh6-lottery-helper/releases/latest) → `FH6LotteryHelper.exe`
（单文件，双击即可运行，无需安装 Python）　**当前版本：v1.1.0**

> 本工具只做两件事，**绝不碰游戏本体**：
> 1. **看屏幕** —— 截屏 + 模板匹配 / Windows 自带 OCR；
> 2. **动键盘** —— 模拟按键（`SendInput` / `PostMessage`）。
>
> 不读游戏内存、不注入 DLL、不改游戏文件、不抓网络包。所以它不会被反作弊识别为「外挂模块」，
> 但同时也意味着：**界面一变，识别就可能失效，需要你自己补模板。**
> （换分辨率已经能自动按比例适配，不必重录。）

---

## 一、能做什么

| 功能 | 说明 |
| --- | --- |
| 智能识别模式 | 截取游戏画面 → 模板匹配 + OCR 判断当前是哪个界面（主界面 / 已拥有 / 新车 / 出售 / 结束），再决定按什么键 |
| 节奏宏模式 | 识别不准时的保底方案：按固定节奏重复一组按键，适合界面完全固定的情况；点击坐标以游戏窗口为原点，窗口挪位置也不点偏 |
| 模板库 | 框选保存界面截图小图，绑定语义角色，随时增删改；支持一键把当前画面存成模板；**可限定匹配区域**，明显减少误判；**换分辨率自动适配** |
| 识别与调试 | 实时看到匹配命中位置、相似度、OCR 文本，方便调阈值、换模板 |
| 悬浮窗 | 置顶小窗，显示进度/统计/识别结果；支持**鼠标穿透**（不挡游戏操作） |
| 全局热键 | 开始/停止/**暂停**/捕获模板/开关悬浮窗，游戏全屏时也能用 |
| 安全保护 | 鼠标甩到屏幕左上角立即急停；可要求「游戏在前台」才发按键；连续识别失败自动停止；画面长时间无变化判定卡住并停止 |
| 失败留痕 | 识别失败 / 判定卡住时自动保存现场截图，设置页一键打开目录，照着补模板 |
| 完成后操作 | 抽完自动关机 / 关闭游戏 / 启动指定程序 / 播放提示音，都能单独开关 |
| 统计 | 抽奖次数、新车数、已拥有数、出售收益、剩余次数 |
| 检查更新 | 设置页手动点，只在那一下联网读一次 GitHub 发布页 |

界面是 PCL 风格的深色主题。

## 二、环境要求

- Windows 10 / 11（64 位）
- Python 3.10+（仅源码运行需要；用打包好的 exe 则不需要）
- 依赖见 `requirements.txt`：

```powershell
pip install -r requirements.txt
```

OCR 用的是 Windows 系统自带的 `Windows.Media.Ocr`，**不需要额外安装 tesseract**。
如果系统里没装中文 OCR 语言包，请到「设置 → 时间和语言 → 语言」里给中文加上「光学字符识别」组件。
装不上也不影响使用：模板匹配是主力，OCR 只是辅助。

## 三、快速开始

### 1. 源码运行

```powershell
cd <项目目录>
python main.py
```

### 2. 打包成 exe

```powershell
powershell -ExecutionPolicy Bypass -File scripts/build.ps1
# 想看报错就加 -Console
```

产物：`dist\FH6LotteryHelper.exe`（单文件，双击即可，不需要装 Python）。

### 3. 自检（建议第一次先跑一遍）

```powershell
python scripts/selftest.py
```

会逐项检查：数据目录、配置读写、Win32 窗口枚举、截屏、模板匹配、模板库读写、
热键解析、Windows OCR、引擎构造。**不会发送任何真实按键**，放心跑。

## 四、怎么用

1. **进游戏**，停在抽奖界面（能看到「抽奖」按钮的那个界面）。
2. 打开助手，到「设置 → 游戏窗口」把关键字填好（默认 `forza`），点「自动识别」，
   确认状态栏提示已锁定到游戏窗口。
3. 到「模板库」页，为几个关键界面各截一张模板：
   - 抽奖主界面 → 角色 `ready`
   - 结果界面「已拥有」→ 角色 `result_owned`
   - 结果界面「新车」→ 角色 `result_new`
   - 抽奖结束 → 角色 `end`
   可以按 `F9` 直接在游戏里框选保存，比来回切窗口快。
4. **给关键模板收窄匹配区域**：点每个模板上的「匹配区域 → 框选匹配区域」，
   把范围框到按钮/标题附近即可。这一步对减少误判帮助最大。
5. 到「流程（智能识别）」页：
   - 选一种「已拥有时的处理方式」：`garage`（回车）/ `gift`（下、回车）/ `sell`（下、下、回车）；
   - 调好各个界面的等待时间（转盘动画大约 5 秒，机器慢就往上加）；
   - 需要的话设「目标抽奖次数」，0 表示不限；
   - 出售时不想冒「误判界面把车卖掉」的风险，就打开「读不到价格就不确认出售」。
6. 按 `F7`（或点左边大按钮）开始，`F11` 暂停/继续，`F8` 停止。
7. 想看看识别对不对，切到「识别与调试」页，或者把悬浮窗打开。

### 默认热键

| 按键 | 作用 |
| --- | --- |
| `F7` | 开始抽奖 |
| `F8` | 停止抽奖 |
| `F11` | 暂停 / 继续 |
| `F9` | 捕获模板（冻结当前画面后框选） |
| `F10` | 显示/隐藏悬浮窗（显示时默认鼠标穿透） |

热键可以在「设置」页改。**如果注册失败**（提示「可能被别的程序占用」），基本都是被
输入法、显卡驱动面板、录屏软件等抢了，换一个或者先关掉那些软件即可。

### 紧急停止

用鼠标**快速甩到屏幕左上角**，助手会立刻停下（这是经典的全屏窗口急停手势）。
嫌烦可以在「设置」页关掉。

## 五、目录结构

```
fh6lottery/
  paths.py        数据目录、日志目录、路径与文本脱敏（界面/日志只显示 %APPDATA%\...）
  config.py       配置读写（JSON，原子写入，缺字段自动补默认值）
  winutil.py      Win32 封装：窗口枚举/按键/热键/前台判断/DPI
  capture.py      截屏（窗口客户区 / 整个虚拟桌面）
  ocr.py          Windows OCR 常驻客户端（PowerShell + WinRT，请求带序号防串包）
  matcher.py      OpenCV 模板匹配（多尺度、灰度缓存、区域限定）
  templates.py    模板库：截图小图 + 语义角色 + 匹配区域 + 采集时窗口尺寸
  actions.py      完成后的操作（关机/关游戏/启动程序/提示音）
  engine.py       抽奖引擎：智能识别状态机 + 节奏宏
  hotkeys.py      全局热键服务
  update.py       检查更新（只在手动点击时联网）
  context.py      应用上下文，把上面这些串起来
  ui/             PCL 风格深色界面（概览/流程/模板库/节奏宏/识别调试/完成动作/设置/日志）
main.py           入口（单实例、DPI、异常钩子、崩溃信息脱敏）
scripts/
  selftest.py     环境自检
  build.ps1       PyInstaller 打包
  make_icon.py    生成图标
```

### 用户数据放哪

全部在 `%APPDATA%\FH6LotteryHelper\` 下：

- `config.json` —— 配置
- `templates.json` + `templates\` —— 模板库
- `logs\app.log`、`logs\crash.log` —— 运行日志、崩溃日志
- `temp\` —— OCR 临时图
- `frames\` —— 冻结画面；`fail_*.png` 是识别失败/卡住时自动留下的现场截图（最多 30 张）

**刻意不写进游戏目录**，这样覆盖安装/卸载助手都不会丢数据，也不会留下一地垃圾。
界面里显示的路径、以及日志与崩溃信息里的路径和用户名都会脱敏，
可以直接贴到公开的 issue 里而不会暴露本机信息。

## 六、常见问题

**识别不到界面 / 一直停在等待**
先去「识别与调试」页看实时命中情况：
- 相似度偏低 → 降低该模板的匹配阈值，或在「设置」里降低全局阈值；
- 相似度够高但认错了 → 给模板加「匹配区域」，把搜索范围收窄到该界面特有的位置；
- 完全没命中 → 游戏更新改了界面，重新截模板（分辨率变化已能自动适配）；
- OCR 文本是空的 → 检查系统是否装了对应语言的 OCR 组件，必要时把「识别语言」改成正确的。

**总是卡在同一个界面 / 反复按同一个键**
助手现在会判断「画面停留过久」并自动停止（默认 20 秒，可在「流程」页调整）。
停下来之后去 `frames\` 目录看留下的现场截图，就能知道它当时把哪一屏当成了什么界面。

**按键在游戏里没反应**
游戏一般都要求**前台**才能收到输入。到「设置 → 按键发送」确认「发送方式」选的是
:「全局键盘事件（推荐，游戏需在前台）」，并保持游戏在前台。
换成「直接投递给游戏窗口（后台模式）」后部分游戏/部分按键收不到，属于游戏自身的限制。

**为什么不用直接读内存 / 发包？**
因为那才是真正会被封号的做法。本工具走的是「人肉操作的自动化」，能力上限低一些，但安全边界清楚。

**会不会误封？**
工具不注入、不改文件、平时不联网（只有你手动点「检查更新」时才读一次发布页），
从技术上说不具备被反作弊针对的特征。
但**任何自动化操作都存在风险**，请自行评估、控制频率，别 24 小时挂机。
